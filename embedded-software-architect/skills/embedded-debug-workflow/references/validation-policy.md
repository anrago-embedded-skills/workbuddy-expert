# 资料来源、版本与验证记录

资料类型：维护与交付规范。用于新增/修改关键流程、代码/命令示例、案例或平台能力说明，以及解释验证覆盖范围。它规定记录方式，不代表集合中的全部条目已获得同等级验证。

## 证据分类

| 类别 | 能支持的结论 | 不能据此声称 |
|---|---|---|
| 来源核对 | 指定版本的官方文档/目标源码存在相应接口或约束 | 当前设备已提供、已配置或运行正确 |
| 静态检查 | 文件、配置、引用、语法或可检查的不变量满足检查范围 | 内核模块已编译、程序功能正确或目标板通过 |
| 工具/教学夹具测试 | 记录的输入下，工具输出或逻辑符合断言 | 输入来自实机、其他系统行为相同或硬件问题已解决 |
| 目标构建 | 记录的 SDK、源码和配置产生了对应构建产物 | 已部署、启动、性能/电气或回归正确 |
| 仿真/模拟 | 记录的模拟环境下相关路径表现符合预期 | 未建模的 DMA、缓存、时序、电气或厂商驱动已验证 |
| 指定板卡验证 | 指定板卡/版本、负载与时间窗口内的实测结果 | 所有板型、SDK 或长期运行均有同样结果 |

这些类别是独立证据，不是一个自动递进的“认证等级”。一个条目可能有工具测试而没有目标构建；没有执行的项目写“未执行/缺少条件”，不得预填通过。

## 关键条目的记录字段

按风险和复杂度记录必要字段，不给每段常识添加机械标签：

```text
资料类型：通用流程 / 平台调查 / 教学案例 / 实测记录
依据：官方文档 URL 与版本，或目标 SDK/源码 revision 和相对路径
适用范围：架构、内核/库/工具版本、硬件与配置前提
示例形式：完整命令 / 参数模板 / 代码片段
已执行：环境、输入、命令、返回码、关键输出与验收范围
未执行：目标构建/仿真/板测等未覆盖项及原因
限制：缺失信息、截断数据、负载/时长和待确认能力
```

来源使用实际核对过的页面或源码。链接到某厂商首页不能支持具体 API、参数或性能保证；同一系列、不同 SDK 的接口名称不能互相代替。依赖目标补丁的行为应注明补丁/配置边界。

## 教学案例

所有构造输入、示意日志、数字和场景都在案例入口标记为教学/合成夹具。案例可以完整展示推理、最小修改和验证计划，但不能写“我们在某板实测修好”来包装未发生的历史。

代码片段不是完整可构建工程。即使片段逻辑经审查，也应说明 target headers、周围生命周期和配置依赖；只有实际运行目标构建并保存结果后，才能升级对应的构建状态。

字段/格式检查只验证夹具结构；真实流程测试需检验行为、错误路径和副作用。不要用“文件存在”或“包含一句正确的话”代替技术正确性或实际读取。

## 平台资料与更新

通用规则放主干，厂商页记录差异和调查入口。未提供匹配 SDK/板卡时，平台页默认保留“未进行本环境 SDK/板测核验”的范围，不把待核实工具或固定目录当事实。

维护时检查同一结论的重复位置：Agent、SKILL.md、平台页、README 和案例。新增参考须从所属技能入口有条件可达；实际读取仍需要宿主正文/工具记录，静态链接不能证明调用成功。

版本/API、部署方式或工具参数变化时更新适用边界。旧示例需保留来源与限制或移除错误执行配方，不能只追加“请自行核实”而保留已知错误。

## 内容效果评测

使用同一原始输入比较无技能与有技能结果，控制模型/上下文/工具/权限条件。分别记录选择与正文取得、关键证据、候选原因、区分实验、无效/错误动作、产物与验收；先确定评价标准，再查看输出。

不把一次正确回答当作跨模型稳定性，也不把输入或任务不同的两次观察计算为调用提升率。无 SDK/板卡时可评估推理和工具行为，目标构建、真实故障恢复和原生 WorkBuddy 加载仍保留未验证状态。
