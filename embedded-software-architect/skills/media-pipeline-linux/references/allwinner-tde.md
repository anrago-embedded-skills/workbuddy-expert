# 全志 Allwinner 平台适配

> 全志平台常见 2D 加速为 **TDE**（Tiled DE），视频引擎为 **VE**（Video Engine），部分新系列用 **DISP** 取代 TDE。

## 硬件加速能力

| 引擎 | 用途 | 访问方式 |
|---|---|---|
| **TDE** | 2D 加速：缩放、格式转换、旋转、合成 | `libtde` API |
| **VE** | 视频编解码（H.264/H.265） | `libVE` API |
| **DISP** | 新系列显示合成/2D（取代 TDE） | `libdisp` API |
| GPU | Mali / PowerVR | EGL / GLES |

---

## TDE（2D 加速）

TDE 的编程模型是**任务队列式**：配置任务描述结构体，一次提交，驱动异步执行。

```c
//典型流程：配置 tde_job 结构 → 提交 → 等待完成 → 释放
struct tde_job job;
job.src_addr = ...; job.dst_addr = ...;
job.src_rect / job.dst_rect;   // 必须注意对齐约束
tde_submit(&job);
tde_wait();
```

**关键约束**：
- 源/目标 buffer 的**宽高、stride 必须对齐**（对齐要求见芯片手册）
- 不支持的格式组合会静默失败，需检查返回值
- 部分系列**不支持任意缩放比例**

---

## VE（视频引擎）

| 系列 | 引擎 |
|---|---|
| V3s / V3d / S3 | TDE + VE |
| A40i / A64 | TDE |
| H616 / H618 | VE + DISP |
| T527 / A527 | 新架构，含 DISP 与新一代 2D |

**注意**：全志不同系列芯片的引擎命名和能力差异大，**必须查具体芯片手册确认**，不要凭系列名推断。

---

## 与 RK 平台的核心差异

| 维度 | RK3588 | 全志 |
|---|---|---|
| 2D 引擎 | RGA2 | TDE（旧）/ DISP（新） |
| 编程模型 | 同步/异步 API，粒度清晰 | 任务队列，异步为主 |
| 生态工具 | rga 命令行可单测 | 依赖厂商库，日志为主 |
| 可观测性 | 好 | 较弱 |

---

## 排查要点

- 摄像头/显示链路拓扑必须用 `media-ctl -p` 确认，不同系列差异大
- 2D 加速调用失败优先怀疑**对齐约束**，其次是格式组合不支持
- 黑屏/花屏问题建议逐环节单独验证（缩放→转换→编码分开测）
- 全志板卡常见 **0 swap**，OOM 排查参考 RK 文档同样的思路（CMA 检查）

---

## 边界与注意

- **TDE/DISP 是全志专属**，不要与 RGA / MDP 混用
- 不同系列引擎能力差异大，**本文档是骨架，具体参数必须查该芯片手册**
- 公开社区资料相对RK 少，不要假设能找到现成方案
- 未在具体芯片上验证的推断，必须明确标注为待验证
